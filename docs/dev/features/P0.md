## Le parcours (`spec/system/p0_journey_spec.rb`)
Par les écrans, avec les rôles qui ont droit à chaque pas :
1. la comptable importe un fichier CODA (3 lignes) ; une seconde fois : « already imported », rien de plus ; un fichier abîmé : refusé avec la ligne en cause ;
2. le moteur a mis en brouillon le paiement exact (communication structurée) ; les indicateurs le disent ; le frais bancaire attend, avec la règle de la société ;
3. l'assistant confirme le frais : un brouillon ; il ne peut pas valider le paiement ;
4. la comptable valide le paiement : la ligne est réglée, la facture payée ;
5. elle verrouille le mois : une écriture datée dedans est refusée (bandeau, pas de bouton, service), et PostgreSQL refuse un changement derrière le dos de l'application ;
6. elle dépose une pièce, la rattache à l'écriture, la lit depuis l'écriture ;
7. invariants sur ce que le parcours a écrit : I1 (double entrée), I2 (balance), I3 (grand livre = balance), I5 (écart de R06 nul), chaîne d'audit intacte.

## Ce que le parcours a fait trouver
Une ligne « matched » (paiement en brouillon, pas encore dans le grand livre) disparaissait de R06 : ni « comptabilisée », ni « sur le relevé non comptabilisée ». Corrigé (`BankReconciliationQuery`) : tant que son écriture n'est pas validée, elle reste dans SN.

## Ce qui n'est pas vérifié
Le rendu visuel des nouveaux écrans (relevés CODA, indicateurs, frise des périodes) n'a été vérifié que par les specs de rendu (rack_test), pas dans un navigateur. Les fichiers CODA et le jeu de référence sont fictifs.

# F03 — Gestion documentaire des pièces justificatives

Statut : **noyau livré, derrière le drapeau `f03`** (par société, éteint par défaut ; le propriétaire le coche dans Settings > Entity). Livré : stockage, dépôt contrôlé, doublons, rattachement, visionneuse, téléchargement, archivage, suppression après terme, panneau sur la fiche d'écriture. **Reste** : extraction (texte PDF, OCR, UBL) et propositions, recherche plein texte, découpe de PDF, vérification d'intégrité, e-mail dédié, antivirus, glisser-déposer avec progression. Voir « Écarts / reporté ».

## Modèle
- `accounting_documents` : société, nom affiché (tel que donné), type MIME **réel**, taille, **SHA-256**, origine (`manual_upload`, `email`, `peppol`, `bank_import`, `scan`), nature (`other`, `purchase_invoice`, `sales_invoice`, `credit_note`, `statement`, `contract`), statut (`inbox`, `linked`, `archived`), `search_text`, `extracted_data` (jsonb), déposé par, `retention_until`, `legal_hold`, `replaces_id`. Le fichier est une pièce jointe Active Storage (`has_one_attached :file`).
- `accounting_document_links` : document ↔ cible polymorphe (écriture, tiers, immobilisation, facture, transaction bancaire), créé par. Un document a plusieurs cibles, une cible plusieurs documents ; un même lien n'existe qu'une fois.
- Extensions PostgreSQL activées : `unaccent`, `pg_trgm` (recherche ici, rapprochement bancaire dans F02).

## Règles
- **Un fichier ne change jamais** : le SHA-256 et la taille sont en lecture seule, un second fichier sous le même document est refusé ; une nouvelle version est un nouveau document qui pointe l'ancien (`replaces_id`).
- **Doublon** : même SHA-256 dans la société → refus, avec le nom du premier document. Une autre société n'est pas un doublon.
- **Lié à une écriture validée** (`Document#locked?`) : ni modifié, ni détaché, ni supprimé, seulement archivé (`ImmutableRecordError`). Le statut seul peut bouger (rattaché, retour à la boîte, archivé).
- **Conservation** : `retention_until` = dépôt + 10 ans (à confirmer, voir `QUESTIONS.md`). Aucune suppression avant ce terme ni sous `legal_hold` ; après, seul un propriétaire (`documents.delete_expired`) peut supprimer, et la suppression est auditée.
- **Rattachement** (`LinkDocument` / `UnlinkDocument`) : la cible doit appartenir à la société du document, un document archivé ne se rattache pas, rattacher fait sortir de la boîte de réception, détacher le dernier lien l'y remet. Les pièces d'une écriture validée ne se détachent pas.

## Dépôt (`Accounting::UploadDocument`)
Rien n'est cru de l'envoi : le type vient **des octets**, jamais de l'extension.
- Acceptés : PDF, PNG, JPEG, TIFF, XML (UBL), CSV, XLSX. 25 Mo au plus. Vide, trop gros, type inconnu (exécutable renommé `.pdf`, script `.csv`, archive ZIP quelconque, texte brut) : refusés avec un message lisible.
- **Intégrité par type** : PDF lisible par `pdf-reader` (un PDF protégé par mot de passe est conservé et marqué `unreadable: password_protected`, sans extraction), PNG avec son bloc `IEND`, JPEG fermé par `FFD9`, XML bien formé, XLSX = archive contenant `xl/workbook.xml`. TIFF : en-tête seulement.
- **XML hostile** : tout XML qui contient `<!DOCTYPE` ou `<!ENTITY` est refusé (aucune entité n'est jamais résolue, le réseau n'est jamais utilisé) ; un UBL n'en a pas besoin.
- Nom affiché tel que donné, nom de stockage normalisé (accents et caractères spéciaux remplacés).
- Audit `document_upload` (nom, empreinte, taille, type, origine), jamais le contenu.

## Écrans (`/accounting/documents`)
- **Liste / boîte de réception** : dépôt de plusieurs fichiers à la fois (chaque refus est signalé avec sa raison), filtres statut / nature / nom, pagination. Les archivés sont masqués par défaut.
- **Visionneuse** : PDF et images dans la page ; XML, CSV, XLSX et TIFF se téléchargent. Détails, liens (vers l'écriture), rattachement par référence d'écriture, changement de nature, archivage, suppression (si terme atteint).
- **Fiche d'écriture** : panneau « Documents » (liste, lien vers la visionneuse, rattachement d'un document de la boîte de réception). Chemin du critère : R02 (compte) → écriture → document.
- **Service de fichiers** (`file`, `download`) : uniquement par l'application (connecté, société et droit vérifiés), jamais par une adresse publique ; une autre société obtient 404. Inline seulement pour PDF/PNG/JPEG, avec `nosniff` ; tout le reste en téléchargement, avec `Content-Security-Policy: default-src 'none'`. Une simple consultation n'est pas auditée ; le téléchargement l'est (`document_download`).

## Droits (`Permissions::MATRIX`)
| Permission | Propriétaire | Comptable | Assistant | Lecteur | Auditeur externe |
|---|---|---|---|---|---|
| `documents.view` (liste, visionneuse, téléchargement) | oui | oui | oui | oui | oui |
| `documents.upload` | oui | oui | oui | non | non |
| `documents.link` (rattacher, détacher, changer la nature) | oui | oui | oui | non | non |
| `documents.archive` | oui | oui | non | non | non |
| `documents.delete_expired` | oui | non | non | non | non |

## Audit
`document_upload`, `document_link`, `document_unlink`, `document_download`, `document_archive`, `document_delete`. La consultation n'est pas journalisée (spec).

## Critères d'acceptation (§6) — état
1. Depuis R01, la pièce en trois clics (compte, écriture, pièce), affichée dans la page — ✅ (la visionneuse est une page, pas un panneau latéral).
2. Même fichier déposé deux fois refusé, avec renvoi au document existant — ✅ (le message nomme le premier document ; pas encore de lien cliquable).
3. Pièce liée à une écriture validée : jamais supprimée, seulement archivée — ✅ `document_spec`, `documents_spec`.
4. Recherche par n° de facture, tiers, montant, avec ou sans accents — ❌ (recherche par nom seulement).
5. PDF de trois factures découpé en trois documents liés au parent — ❌.
6. Un octet modifié dans le fichier stocké détecté par `documents:verify` — ❌.
7. Lien d'une autre société refusé — ✅ (404, `documents_spec`).
8. PDF exporté pour un auditeur filigrané — ❌ pour les documents (les rapports le sont, F01).

## Écarts / reporté
- **Extraction et propositions** (couche texte du PDF, OCR Tesseract pour les scans, lecture directe de l'UBL, champs proposés avec la zone d'origine, bouton « créer l'écriture ») : non faits. Outils présents sur la machine de développement : `tesseract`, `pdftotext`, `pdfinfo` ; **l'image Docker de production devra les inclure**.
- **Recherche plein texte** (`unaccent`, `tsvector`, configurations fr/nl/en, filtres tiers/période/montant) : seule la recherche par nom existe. Les extensions et la colonne `search_text` sont prêtes.
- **Découpe d'un PDF**, **`documents:verify`** (recalcul des empreintes, alerte R19), **suspension légale** (`legal_hold` est géré par le modèle mais n'a pas d'écran), **rétention par type**.
- **Adresse e-mail dédiée** (ActionMailbox), **dépliage des archives ZIP**, **antivirus** (ClamAV), **glisser-déposer avec barre de progression**, **visionneuse en panneau latéral** avec zoom/rotation, **filigrane** du nom de l'auditeur sur la visionneuse.
- **Pièces déjà reçues** (UBL et PDF Peppol attachés aux factures) : pas migrées vers `accounting_documents`.
- **Stockage chiffré au repos, S3** : le service Active Storage reste le disque local ; le chiffrement dépend du volume (à décider avec l'hébergement).
- **Images** : seul le contrôle d'en-tête et de fin est fait, pas de décodage.
- Le contrôle des fichiers CSV repose sur l'extension `.csv` **et** un contenu textuel (un CSV n'a pas de signature).

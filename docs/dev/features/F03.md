# F03 — Gestion documentaire des pièces justificatives

Statut : **noyau et extraction livrés, derrière le drapeau `f03`** (par société, éteint par défaut ; le propriétaire le coche dans Settings > Entity). Livré : stockage, dépôt contrôlé, doublons, rattachement, visionneuse, téléchargement, archivage, suppression après terme, panneau sur la fiche d'écriture, **extraction (texte du PDF, OCR, UBL) avec propositions, confirmation champ par champ, création d'un brouillon de facture**. **Reste** : recherche plein texte, découpe de PDF, vérification d'intégrité, e-mail dédié, antivirus, glisser-déposer avec progression. Voir « Écarts / reporté ».

## Modèle
- `accounting_documents` : société, nom affiché (tel que donné), type MIME **réel**, taille, **SHA-256**, origine (`manual_upload`, `email`, `peppol`, `bank_import`, `scan`), nature (`other`, `purchase_invoice`, `sales_invoice`, `credit_note`, `statement`, `contract`), statut (`inbox`, `linked`, `archived`), `search_text`, `extracted_data` (jsonb), déposé par, `retention_until`, `legal_hold`, `replaces_id`. Le fichier est une pièce jointe Active Storage (`has_one_attached :file`).
- `accounting_document_links` : document ↔ cible polymorphe (écriture, tiers, immobilisation, facture, transaction bancaire), créé par. Un document a plusieurs cibles, une cible plusieurs documents ; un même lien n'existe qu'une fois.
- Extensions PostgreSQL activées : `unaccent`, `pg_trgm` (recherche ici, rapprochement bancaire dans F02).

## Règles
- **Un fichier ne change jamais** : le SHA-256 et la taille sont en lecture seule, un second fichier sous le même document est refusé ; une nouvelle version est un nouveau document qui pointe l'ancien (`replaces_id`).
- **Doublon** : même SHA-256 dans la société → refus, avec le nom du premier document. Une autre société n'est pas un doublon.
- **Lié à une écriture validée** (`Document#locked?`) : ni modifié, ni détaché, ni supprimé, seulement archivé (`ImmutableRecordError`). Le statut seul peut bouger (rattaché, retour à la boîte, archivé).
- **Conservation** : `retention_until` = dépôt + 10 ans (à confirmer, voir `QUESTIONS.md`). Aucune suppression avant ce terme ni sous `legal_hold` ; après, seul un propriétaire (`documents.delete_expired`) peut supprimer, et la suppression est auditée.
- **Rattachement** (`LinkDocument` / `UnlinkDocument`) : la cible doit appartenir à la société du document, un document archivé ne se rattache pas, rattacher fait sortir de la boîte de réception, détacher le dernier lien l'y remet. Les pièces d'une écriture validée ne se détachent pas.

## Dépôt (`Accounting::UploadDocument`)
Rien n'est cru de l'envoi : le type vient **des octets**, jamais de l'extension.
- Acceptés : PDF, PNG, JPEG, TIFF, XML (UBL), CSV, XLSX. 25 Mo au plus. Vide, trop gros, type inconnu (exécutable renommé `.pdf`, script `.csv`, archive ZIP quelconque, texte brut) : refusés avec un message lisible.
- **Intégrité par type** : PDF lisible par `pdf-reader` (un PDF protégé par mot de passe est conservé et marqué `unreadable: password_protected`, sans extraction), PNG avec son bloc `IEND`, JPEG fermé par `FFD9`, XML bien formé, XLSX = archive contenant `xl/workbook.xml`. TIFF : en-tête seulement.
- **XML hostile** : tout XML qui contient `<!DOCTYPE` ou `<!ENTITY` est refusé (aucune entité n'est jamais résolue, le réseau n'est jamais utilisé) ; un UBL n'en a pas besoin.
- Nom affiché tel que donné, nom de stockage normalisé (accents et caractères spéciaux remplacés).
- Audit `document_upload` (nom, empreinte, taille, type, origine), jamais le contenu.

## Écrans (`/accounting/documents`)
- **Liste / boîte de réception** : dépôt de plusieurs fichiers à la fois (chaque refus est signalé avec sa raison), filtres statut / nature / nom, pagination. Les archivés sont masqués par défaut.
- **Visionneuse** : PDF et images dans la page ; XML, CSV, XLSX et TIFF se téléchargent. Détails, liens (vers l'écriture), rattachement par référence d'écriture, changement de nature, archivage, suppression (si terme atteint).
- **Fiche d'écriture** : panneau « Documents » (liste, lien vers la visionneuse, rattachement d'un document de la boîte de réception). Chemin du critère : R02 (compte) → écriture → document.
- **Service de fichiers** (`file`, `download`) : uniquement par l'application (connecté, société et droit vérifiés), jamais par une adresse publique ; une autre société obtient 404. Inline seulement pour PDF/PNG/JPEG, avec `nosniff` ; tout le reste en téléchargement, avec `Content-Security-Policy: default-src 'none'`. Une simple consultation n'est pas auditée ; le téléchargement l'est (`document_download`).

## Extraction et propositions
Tout ce qui est lu d'un document est une **proposition** : jamais une écriture, jamais une donnée tant qu'une personne ne l'a pas confirmée. Rien ne quitte le serveur (l'OCR est le `tesseract` local) ; aucun service externe.
- **Déroulement** : au dépôt, le document passe en statut de lecture `pending` et `Accounting::ExtractDocumentJob` est mis en file (3 tentatives, délai croissant, exécuté dans la société du document). Statuts visibles sur la fiche et dans la liste : `pending`, `done`, `unreadable` (protégé ou abîmé), `low_confidence` (OCR pas assez sûr : rien n'est gardé), `not_applicable` (tableur, CSV, XML qui n'est pas une facture), `failed` (avec l'erreur). « Read again » relance la lecture.
- **Extracteurs** (`Accounting::Extractors::*`, interchangeables) : `PdfText` (couche texte, pages séparées par un saut de page), `Ocr` (images, et PDF sans couche texte via `pdftoppm`; `tesseract --psm 4`; langues installées parmi fra, nld, eng; confiance = moyenne des mots, seuil 60 ; 10 pages au plus ; 90 s de délai ; sans shell), `Ubl` (lecture directe de l'XML BIS 3.0, chaque champ cite son élément, aucune entité résolue).
- **Champs proposés** (`Accounting::DocumentFieldParser`, libellés en français, néerlandais et anglais) : fournisseur (par numéro de TVA, jamais deviné : seulement si un tiers de la société porte ce numéro), numéro de TVA, numéro de facture, date, échéance, total HTVA, TVA, total TVAC, IBAN, communication structurée. Les numéros à clé de contrôle sont **validés** (IBAN mod 97 avec longueur par pays, TVA belge, communication structurée) ; les montants sont recoupés (HTVA + TVA = TVAC : confiance « haute », sinon « basse », signalée « Check this one »). Chaque proposition garde **la ligne et la page** d'où elle vient.
- **Confirmation** (`ConfirmDocumentField`, permission `documents.link`) : une personne confirme ou corrige chaque champ ; la valeur est contrôlée selon sa nature, l'audit garde ce qui était proposé et ce qui a été confirmé (`document_field_confirm`), un champ confirmé n'est **jamais écrasé** par une nouvelle lecture. Refusé sur un document figé par une écriture validée.
- **Créer l'écriture** (`CreateInvoiceFromDocument`, bouton « Create a draft invoice ») : un **brouillon de facture fournisseur** (en-tête : fournisseur choisi, dates, numéro, montants de référence ; valeur confirmée avant valeur proposée) lié au document, **sans aucune ligne** : la personne ajoute les lignes et leurs comptes. Rien n'est validé. Devise : EUR, ou une devise reconnue dont le taux est connu (jamais un taux deviné). **Doublon probable** (même fournisseur, même numéro, facture non annulée) : refusé, avec le numéro de la facture déjà là ; contournable avec un motif, audité (`document_duplicate_override`). L'audit `document_invoice_draft` liste les champs utilisés qui n'étaient que des propositions.

## Ajouts de la fin de F03
- **Découpe** (`split`), **suspension légale** (motif obligatoire, propriétaire seul, bloque la suppression), **rétention par nature** (ne raccourcit jamais), **intégrité** (`integrity_status`, C18).
- **ZIP** : déplié à l'envoi (`UploadFiles`), limites `config.x.document_archive_limits` (50 fichiers, 100 Mo, ratio 100), pas d'archive imbriquée ni chiffrée, nom seul conservé.
- **Antivirus** : `DOCUMENT_VIRUS_SCAN_COMMAND` (lit le fichier sur stdin, 0 = sain, 1 = infecté) ; scanner absent ou en panne = dépôt refusé, sauf `..._FAIL_OPEN`. Sans commande configurée, aucun contrôle.
- **E-mail** : `DocumentsMailbox`, adresse secrète `documents+<jeton>@DOCUMENTS_MAIL_DOMAIN` par société (Settings > Entity, remplaçable par le propriétaire, audité). Pièces jointes déposées en origine « email » avec expéditeur / objet ; images en ligne < 10 Ko ignorées ; adresse inconnue ou drapeau f03 éteint : rien créé, aucune réponse. Production : `config.action_mailbox.ingress = :relay` et un mot de passe d'ingress (`RAILS_INBOUND_EMAIL_PASSWORD`), le serveur de messagerie relayant vers `/rails/action_mailbox/relay/inbound_emails`.
- **Glisser-déposer** avec barre de progression (`dropzone_controller.js`) ; réponse JSON vide, les messages attendent sur la liste.

## Audit
`document_upload`, `document_link`, `document_unlink`, `document_download`, `document_archive`, `document_delete`, `document_field_confirm`, `document_invoice_draft`, `document_duplicate_override`. La consultation n'est pas journalisée (spec). (*) créer un brouillon de facture exige aussi `records.write`.

## Critères d'acceptation (§6) — état
1. Depuis R01, la pièce en trois clics (compte, écriture, pièce), affichée dans la page — ✅ (la visionneuse est une page, pas un panneau latéral).
2. Même fichier déposé deux fois refusé, avec renvoi au document existant — ✅ (le message nomme le premier document ; pas encore de lien cliquable).
3. Pièce liée à une écriture validée : jamais supprimée, seulement archivée — ✅ `document_spec`, `documents_spec`.
4. Recherche par n° de facture, tiers, montant, avec ou sans accents — ✅ colonne générée `search_blob` (nom + texte lu + valeurs des champs, sans accents, minuscules) + index GIN trigramme ; filtres tiers, période, montant, origine, statut, nature.
5. PDF de trois factures découpé en trois documents liés au parent — ✅ `SplitDocument` (plages « 1-2, 3 », le parent n'est jamais modifié).
6. Un octet modifié dans le fichier stocké détecté par `documents:verify` — ✅ `VerifyDocument`, `VerifyDocumentsJob` (hebdomadaire en production), contrôle bloquant C18, bandeau sur la fiche.
7. Lien d'une autre société refusé — ✅ (404, `documents_spec`).
8. PDF exporté pour un auditeur filigrané — ✅ `WatermarkFile` (Ghostscript, nom de l'auditeur + métadonnée) ; un type non marquable n'est servi que si l'export est autorisé.

## Écarts / reporté
- **Recherche** : trigramme (`LIKE` sur `search_blob`) plutôt que `tsvector` : sous-chaînes et numéros de facture fonctionnent sans configuration de langue. Écart assumé par rapport à la spec.
- **Zone d'origine d'un champ** : la proposition cite la **ligne et la page**, pas un rectangle sur le document (pas de surbrillance dans la visionneuse).
- **Qualité de la lecture** : les motifs sont des heuristiques (libellés fr/nl/en usuels). Une facture à la mise en page inhabituelle donne moins de champs, ou des champs « à vérifier ». Les propositions sont vérifiées par une personne, jamais appliquées seules. Pas de lecture des lignes de facture (quantités, prix, comptes) : le brouillon n'a que l'en-tête.
- **Autres numéros de TVA** : seuls les numéros belges sont lus et validés dans le texte (l'UBL donne les autres tels quels).
- **OCR** : seule la langue anglaise est installée sur la machine de développement ; le code utilise fra et nld dès qu'elles sont présentes (`tesseract-ocr-fra`, `tesseract-ocr-nld` dans l'image Docker de production, avec `tesseract-ocr` et `poppler-utils`). Mode de segmentation 4 : un tableau à plusieurs colonnes peut être mal lu.
- **Ajout d'un champ non proposé** : le service l'accepte (`ConfirmDocumentField`), mais l'écran ne propose que les champs lus.
- **Visionneuse en panneau latéral** avec zoom/rotation : non faite (la visionneuse est une page).
- **Pièces déjà reçues** : `bin/rails documents:import_invoice_attachments` (idempotent, par SHA-256) les verse dans le magasin, origine Peppol, liées à la facture. À lancer une fois par société ; elles ne sont pas lues par l'extraction.
- **Stockage chiffré au repos, S3** : le service Active Storage reste le disque local ; le chiffrement dépend du volume (à décider avec l'hébergement).
- **Images** : seul le contrôle d'en-tête et de fin est fait avant lecture, pas de décodage.
- Le contrôle des fichiers CSV repose sur l'extension `.csv` **et** un contenu textuel (un CSV n'a pas de signature).

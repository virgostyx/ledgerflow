# A04 — Confidentialité et gouvernance des données

Statut : consentement, modes par classe, masqueur, pseudonymisation réversible, avertissement avant envoi, charge utile consultable, rétention, export et effacement livrés et testés. Les flux sont décrits dans `DATA_PROCESSING.md` ; les questions juridiques dans `QUESTIONS.md`.

## Ce qui existe
- **Consentement** (`Agent::Consent`) : par version du texte (`Agent::Consent::VERSION`, `app/views/agent/settings/_consent.html.erb`). Sans consentement à la version courante, `Agent::Access` répond `:consent_missing`. Un spec échoue quand le texte change sans que la version change.
- **Réglages** (`Agent::Setting`) : mode par classe (`send`, `mask`, `block`), mode restreint, rétention. Seul le propriétaire (`agent.configure`) les change ; chaque changement est dans la piste d'audit.
- **Masqueur** (`Agent::Redactor`) : appelé par `Agent::ModelGateway` juste avant l'envoi, sur la consigne, l'historique, les résultats d'outils et la question. Deux passes : les champs déclarés par les outils selon leur classe, puis un balayage de tout texte (`Agent::Identifiers` : IBAN, numéro national, numéro de TVA ou d'entreprise avec chiffres de contrôle ; noms des tiers qui sont ou peuvent être des personnes physiques). Carte bancaire et mot de passe : jamais.
- **Pseudonymes** (`Agent::Pseudonyms`, `agent_pseudonyms`) : `PERSONNE_nnn`, `TVA_nnn`, propres à la conversation, chiffrés. Les arguments d'outil du modèle sont « révélés » avant exécution ; les réponses sont affichées et diffusées avec les vrais noms ; un jeton inventé est laissé tel quel et enregistré.
- **Ce que la personne tape** (`Agent::SensitiveInput`) : avertissement avant envoi avec le choix selon le mode de la société ; carte et mot de passe refusés.
- **« Voir ce qui a été envoyé »** : la charge utile masquée, chiffrée, sur chaque réponse, avec le compte des valeurs masquées par classe.
- **Rétention** (`Agent::RetentionJob`, chaque nuit) et suppression par l'utilisateur : le contenu part, la piste d'audit reste, les extraits des événements de sécurité partent avec la conversation.
- **Export** des conversations de la personne ; **recherche, export et effacement** d'une personne physique par un propriétaire (`/agent/subject_requests`), avec motif et empreinte du nom dans la piste d'audit.
- **Page de confidentialité** pour tous ceux qui peuvent utiliser l'agent.
- `partners.is_natural_person` (nullable, sélecteur sur la fiche du tiers).

## Critères d'acceptation (§7) et tests
| # | Critère | Test |
|---|---|---|
| 1 | Par défaut, aucun IBAN complet, nom de personne physique ni TVA dans la charge utile | `redactor_spec`, `runner_spec` (« what leaves for the model »), `model_gateway_spec` (charge utile réellement transmise) |
| 2 | En mode `block`, aucune valeur de la classe, quel que soit l'outil | `redactor_spec`, `runner_spec` ; la généralité repose sur les classes déclarées par chaque outil (A02) et sur le balayage de tout texte |
| 3 | Pseudonymisation réversible : la personne lit les vrais noms, le modèle jamais | `pseudonyms_spec`, `runner_spec`, `answer_job_spec`, `conversations_spec` |
| 4 | IBAN ou numéro national saisi : avertissement, choix respecté | `sensitive_input_spec`, `conversations_spec` |
| 5 | Sans consentement à la version courante, l'agent est indisponible | `access_spec`, `settings_spec` |
| 6 | La rétention supprime le contenu et garde les métadonnées d'audit | `retention_job_spec` |
| 7 | « Voir ce qui a été envoyé » reproduit la charge utile masquée | `runner_spec` (égalité avec ce que la passerelle a reçu), `conversations_spec` |
| 8 | Hors production, aucun appel au vrai fournisseur | `model_gateway_spec` |
| 9 | Export et effacement pour une personne physique | `privacy_rights_spec` (conversations ; notes et propositions n'existent pas encore) |

## Écarts et reste à faire
- Voir `QUESTIONS.md` (A04) : charge utile conservée, questions tapées conservées, mode `mask` des montants, tiers inconnus masqués, chiffrement déterministe.
- **Mode de document** (A09) et **budget** (§16) : pas encore dans les réglages.
- Le titre d'une conversation reste les 60 premiers caractères de la question (pas de modèle `light`) : un titre peut donc contenir un nom ; il n'est pas envoyé au modèle, mais il est affiché et exporté.
- **Mots de passe** : reconnus quand ils suivent « mot de passe », « password », « wachtwoord », « pwd » ou « passcode » avec `:` ou `=`. Une phrase libre (« mon code est 1234 ») n'est pas vue.

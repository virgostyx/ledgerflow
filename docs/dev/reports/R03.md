# R03 — Journaux

Statut : vue centralisatrice livrée + détection des trous de numérotation. La vue détaillée existait déjà.

## Vue détaillée
**Déjà couverte par l'existant** : `Accounting::JournalEntriesController#index` (`/accounting/journal_entries`) offre déjà écritures paginées (Pagy), filtrables par journal/statut/date/référence via `autofilter`, avec lignes dépliables sur la page de l'écriture. Rien reconstruit ici — reuse pur.

## Vue centralisatrice (`GET /accounting/reports/journal_summary`)
Par journal et par mois (calendaire — pas encore aligné sur le rang dans l'exercice comme le fait `Reports::Period.month`) : nombre d'écritures, total débit, total crédit. Bandeau d'alerte listant les trous de numérotation détectés par journal.

## Détection des trous de numérotation
`Accounting::JournalNumberingGaps` (`app/services/accounting/`) : parse le suffixe numérique des références (`PREFIXAAAA/NNNN`), retourne les numéros manquants entre le premier et le dernier numéro posté du journal pour l'exercice.

## Critères d'acceptation (§6) — état
5. ΣDébit = ΣCrédit par journal et par période — ✅ vrai par construction (double-entrée), vérifié explicitement par un test dédié.
6. Rupture de numérotation créée volontairement est détectée — ✅ testé.

## Écarts / reporté
- Pas de cellule cliquable de la vue centralisatrice vers la vue détaillée filtrée (à ajouter : un lien `journal_id`+mois vers `journal_entries#index`).
- Regroupement par mois calendaire, pas par rang dans l'exercice (`Reports::Period.month`) — un exercice décalé (non-janvier) afficherait donc les mois dans l'ordre calendaire, pas dans l'ordre de l'exercice.
- Pas d'export CSV/XLSX/PDF pour cette vue.
- Pas de filtre par plage de numéros ni par utilisateur sur la vue détaillée existante (limité aux filtres déjà supportés par `JournalEntriesController`).

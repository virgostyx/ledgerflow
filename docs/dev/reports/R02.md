# R02 — Grand livre

Statut : v1 livrée (ouverture/mouvements/clôture par compte, filtres tiers/journal/lettrage, drill-down tiers).

## Filtres
`account_id` (requis) · `date_from`/`date_to` · `partner_id` · `journal_id` · `lettering` (`lettered`/`unlettered`).

## Colonnes
Date · Référence · Libellé · Tiers (lien vers le grand livre auxiliaire) · Débit · Crédit · Solde cumulé · Code de lettrage.
Trois lignes fixes par section : **Report** (solde d'ouverture), lignes de mouvement, **Total des mouvements** + **Solde de clôture**.

## Règles de calcul
- `opening_balance` = solde des lignes avant `date_from`, signé selon le sens normal du compte (une seule requête SQL, `COALESCE(SUM...))`).
- Solde cumulé = ouverture + Σ(débit−crédit signé) au fil des lignes.

## Drill-down
- Nom du tiers → grand livre auxiliaire (même compte, `partner_id` ajouté).
- Référence de l'écriture → page de l'écriture complète (`accounting_journal_entry_path`, déjà existante).

## Critères d'acceptation (§6) — état
1. Solde clôture = ligne balance (I3) — ✅ (`spec/invariants/i3_ledger_matches_trial_balance_spec.rb`, toujours valide : seul un paramètre optionnel a été ajouté).
2. Solde cumulé de la dernière ligne = solde de clôture — ✅ garanti par construction, testé (`carries into running_balance...`).
4. Recherche texte/montant ne modifie pas les totaux d'autres comptes — ✅ trivialement vrai (une requête = un compte).
7. Performance : requêtes en nombre fixe (pas de N+1), vérifié par `spec/performance/queries_spec.rb` (mis à jour : 3 requêtes réelles + introspection de schéma ponctuelle).

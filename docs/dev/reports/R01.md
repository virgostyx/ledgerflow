# R01 — Balance générale et de vérification

Statut : v1 livrée (mode général, comparatif N-1, drill-down, 3 exports). Voir "Écarts" ci-dessous pour ce qui reste.

## Filtres
- `fiscal_year_id` (défaut : exercice ouvert)
- `as_of` (date de fin de période, défaut : fin d'exercice)
- `comparative` (`previous_year` ou vide)

## Colonnes (mode général)
Code · Libellé · Ouverture Débit · Ouverture Crédit · Mouvements Débit · Mouvements Crédit · Clôture Débit · Clôture Crédit, + Clôture N-1 · Variation si `comparative=previous_year`.

## Règles de calcul
- Ouverture = lignes validées de l'exercice avec `entry_date < as_of`'s period start (`date_from`, ici toujours le début d'exercice tant que le filtre de sous-période n'est pas exposé en UI). Mouvements = lignes entre `date_from` et `as_of`, brutes. Clôture = ouverture + mouvements, nette, placée en Débit si positive sinon en Crédit.
- Comparatif N-1 : recherche `Accounting::FiscalYear.find_by(year: fiscal_year.year - 1)` ; absent → variation à 0/nil sans erreur.
- Exports (CSV/XLSX/PDF) et écran consomment le même `Reports::Result` — mêmes totaux par construction.

## Drill-down
Clic sur le code compte → grand livre (`general_ledger?account_id=…&fiscal_year_id=…`), mêmes filtres.

## Critères d'acceptation (§5) — état
1. Σ Débit = Σ Crédit par groupe de colonnes — garanti par construction (chaque écriture, datée une seule fois, tombe entièrement dans "ouverture" ou "mouvements", jamais scindée) ; pas de test dédié séparé de I1/I2.
2. Clôture = ouverture + mouvements — vrai par construction SQL (une seule somme scindée par `FILTER`), non testé isolément.
3. **Non fait** : niveaux de détail (classe / 2 chiffres / 3 chiffres / compte, ROLLUP) — reporté, v1 = niveau compte complet uniquement.
4. Solde compte = grand livre (I3) — ✅ couvert par `spec/invariants/i3_ledger_matches_trial_balance_spec.rb`.
5. **Partiel** : le mode « vérification » (colonnes Solde Débiteur/Créditeur) n'a pas d'écran dédié ; les données sous-jacentes (`closing_display_debit/credit`) sont déjà mode-agnostic, donc un futur toggle ne recalculerait rien.
6. Exports = écran — garanti par construction (même `Reports::Result`), pas de test explicite de comparaison bit-à-bit.
7. **Non fait** : performance < 1 s sur 200 000 lignes — aucun spec `:perf` écrit (prévu par la spec comme suite nocturne séparée).
8. Isolation multi-société — ✅ (`entity scoped report` sur `TrialBalanceQuery`).

## Écarts / reporté
- Filtres non exposés en UI : plage de comptes, classes, journaux, inclusion des brouillons, masquer soldes nuls/sans mouvement.
- Pas d'avertissement « compte inconnu » ni « opening_computed ».
- Pas de pagination HTML au-delà de 5000 comptes.
- i18n : labels en anglais uniquement pour les nouvelles colonnes (fr/nl à ajouter — voir `docs/dev/reports/QUESTIONS.md`).
- Le format de colonnes diffère entre `Reports::TableComponent` (`{key:, label:}`) et `Reports::Exporters::*` (`[label, key]`) ; un adaptateur (`trial_balance_export_columns`) les réconcilie pour l'instant — à unifier si un second rapport en a besoin (règle des trois occurrences).

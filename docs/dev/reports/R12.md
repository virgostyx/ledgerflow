# R12 — Analytics and margin (v1)

Extends the existing `accounting_analytical_*` model (no parallel `analytic_*` tables).

- Migration `20260929000000`: `accounting_analytical_annotations.percentage numeric(5,2)` (default 100, check 0 < p ≤ 100); uniqueness moves from (line, axis) to (line, axis, account) so a line can be split across accounts of one axis. Existing rows keep 100 %. Reversible.
- Validation: the sum of percentages of a line on one axis may not exceed 100.
- `Accounting::AnalyticPivotQuery`: class 6/7 rows × analytical accounts (or months), each line weighted by its percentage, "Non ventilé" = row total − allocated part. All aggregation in SQL over `posted_lines`. Page `reports/analytic_pivot`.
- `Accounting::AnalyticMarginQuery`: revenue − direct costs, margin %, unallocated expenses spread on separate "overhead" figures by key `:revenue` or `:direct_costs` (last account absorbs the rounding cent). Page `reports/analytic_margin`.
- I8 (`spec/invariants/i8_*`): pivot net result = R08 result heading 9904 on the reference ledger, which now includes an analytic scenario (3 projects, one 50/50 line, one full, rest unallocated).

## Decisions / deferrals
- A partial split (e.g. 60 %) is accepted; the remainder shows as "Non ventilé" (prudent, keeps I8). The spec's "≠ 100 % refused at validation" would need a guard at posting: deferred, wider blast radius.
- Overhead = all unallocated *expenses* (not only a designated general-costs account set).
- Deferred: secondary axis, comparison N-1, filter by account/heading, drill-down to R02 by analytical account, archived-account handling checks, CSV/XLSX exports, `invoice` line annotation UI for percentages (existing forms still create 100 % annotations).

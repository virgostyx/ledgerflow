# R08 — Compte de résultat

Statut : v1 livrée. Ajout principal : la **vue mensualisée**, la fonctionnalité distinctive de R08 qui manquait entièrement.

## Vue annuelle
Héritée de `Accounting::AnnualAccounts` (voir R07.md) : rubrique · exercice N · N-1 · Variation € · Variation %. Sous-totaux déjà présents dans le modèle BNB : résultat d'exploitation (9901), résultat avant impôts (9902/9903), résultat de l'exercice (9904).

## Vue mensualisée (nouveau)
`Accounting::AnnualAccounts#monthly_income_rows` : 12 colonnes rangées par **rang dans l'exercice** (réutilise `Reports::Period.month`, pas calendaires — reste correct pour un exercice décalé), + Cumul, + Cumul N-1. Un mois sans mouvement affiche 0 (`BigDecimal`), jamais une case vide.

Réutilise directement les champs `movement_debit`/`movement_credit` de `Accounting::TrialBalanceQuery` (ajoutés pour R01) — aucune nouvelle requête agrégée écrite à la main, juste `figures_for` paramétrée par les champs débit/crédit à lire (`:total_debit/:total_credit` pour l'annuel, `:movement_debit/:movement_credit` pour un mois).

Accessible via `?view=monthly` sur `/accounting/reports/annual_accounts`, avec un toggle Annual/Monthly.

## Critères d'acceptation (§9) — état
2. Résultat R08 = ligne Résultat R07 pour la même date — ✅ trivialement vrai : même moteur, même `figures_for`, un seul calcul du résultat (rubrique 9904), affiché dans les deux statements.
3. Σ 12 mois de la vue mensualisée = vue annuelle, rubrique par rubrique — ✅ testé explicitement (`sums the 12 months into the cumulative figure, matching the annual view`).

## Écarts / reporté
- Pas de vue trimestrielle (`view=quarterly`) — seule la vue mensuelle a été construite ; trivial à ajouter en groupant 3 mois si besoin (même mécanisme).
- Pas de "% du chiffre d'affaires" en vue annuelle.
- Pas de drill-down cellule mensuelle → grand livre du mois (même écart que R07 : la granularité par compte n'existe pas encore dans cette vue).

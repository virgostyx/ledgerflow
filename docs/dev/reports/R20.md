# R20 — Audit and closing files (v1)

Page `/accounting/closing_bundle` (sidebar "Closing Files"; auditors and above). Every download is written to the audit trail (`export_closing_bundle`, `export_audit_export`, `export_filing_data`), which also closes the "exports" gap left in R18.

- **Closing bundle** — `Accounting::ClosingBundle`: ZIP with PDFs of R01, R02, R04 (customers and suppliers), R07, R08, R09, R16, R17; the frozen bank reconciliations of R06 as JSON (result + its content hash); `filing_data.json`; `manifest.json` (SHA-256 and size of each file, generation date). PDFs are made by the same query objects as the screens and carry no timestamp, and the ZIP uses a fixed entry time and sorted paths: regenerating from the same data gives byte-identical files (only the manifest's `generated_at` differs — tested). `Accounting::ClosingBundle.verify` and `rake closing_bundle:verify FILE=…` recompute every hash and name mismatching or missing files (tested).
- **Full audit export** — `Accounting::AuditExport`: ZIP of flat CSV and JSON for entries with all their lines (one row per line), chart of accounts, partners, journals and VAT codes. Enum columns are written by name. SAF-T is not produced (on explicit request only, per the spec).
- **Filing data** — `Accounting::FilingData`: balance sheet and income statement amounts per rubric code (R07/R08) and the VAT declarations' grids (R09) as JSON. Official XML filings from the official schemas are a separate phase.

## Limits / deferred
- The PDFs use the generic tabular exporter (Prawn): R02 lists every line of every account of the year, which can be a large file; no page breaks per account, no rubric hierarchy formatting. R04 is taken at the year end.
- "PDF totals equal the screens" is verified structurally (same queries) and by checking the figures appear in the trial balance and VAT PDFs; there is no per-report text comparison for all eight.
- The audit export streams nothing: it loads each dataset into memory (pluck), fine for normal volumes, to revisit for very large ledgers.
- No signed manifest (a hash list proves integrity of the files against the manifest, not its authorship).

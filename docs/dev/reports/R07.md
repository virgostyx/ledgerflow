# R07 — Bilan

Statut : v1 livrée en étendant `Accounting::AnnualAccounts` existant (déjà le moteur de rubriques que le §9 demande, sous forme YAML plutôt que tables DB).

## Ce qui existait déjà (avant ce travail)
`Accounting::AnnualAccounts` + `config/annual_accounts/company_abridged.yml` : bilan actif/passif + compte de résultat par rubrique BNB, comparatif N-1, détection des "Non classé", résultat de l'exercice replié dans le report à nouveau, export XLSX, page `annual_accounts`.

## Ajouté (§9)
- **Variation en montant / en %** par rubrique (`Row#variation_amount`/`#variation_pct`, blanc si N-1 = 0, jamais infini).
- Colonnes affichées dans `_annual_statement.html.erb`.

## Moteur de rubriques — écart de conception assumé
Pas de tables `report_templates`/`report_lines`/`report_line_accounts` : le modèle reste piloté par un fichier YAML (`prefixes`/`side`/`sum`/`add`), qui remplit exactement le même rôle ("somme de plages de comptes" ou "formule sur d'autres rubriques") sans le coût de construire un CRUD dessus. Un seul modèle (BNB abrégé) — pas de "Présentation de gestion" avec EBITDA.

## Vraie correction trouvée en testant l'invariant I6
Le jeu de référence utilisait le compte `499000` (comptes d'attente) comme contrepartie technique dans les scénarios de lettrage — ce compte n'était rattaché à aucune rubrique, cassant l'équilibre actif=passif (I6) et le critère #7. Corrigé en rattachant `499` à la rubrique `490/1` (comptes de régularisation actif) dans le YAML — un compte de suspens générique y trouve raisonnablement sa place.

## Critères d'acceptation (§9) — état
1. Actif = Passif, résultat inclus (I6) — ✅ déjà couvert par `balanced?`, formalisé dans `spec/invariants/i6_balance_sheet_equals_income_result_spec.rb`, vérifié sur le jeu de référence.
4. Changer le niveau de détail ne modifie aucun total — non applicable : un seul niveau de détail existe (pas de granularité configurable), donc rien à casser mais rien à tester non plus.
5. N-1 = clôture exercice précédent (R01) — ✅ déjà couvert.
7. Aucun compte du jeu de référence resté "Non classé" — ✅ vérifié (et corrigé) via l'invariant I6.
